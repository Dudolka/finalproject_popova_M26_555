# ValutaTrade Hub

**ValutaTrade Hub** — учебное консольное приложение на Python для виртуальной торговли валютами и мониторинга обменных курсов. Проект создан в рамках магистратуры НИЯУ МИФИ.

Все операции выполняются с **виртуальными средствами**: приложение не проводит реальные платежи и не предназначено для инвестирования или промышленной эксплуатации.

## Возможности

- Регистрация и авторизация пользователей; создание пустого портфеля при регистрации и раздельное хранение данных.
- Пополнение баланса USD, покупка и продажа поддерживаемых валют за USD с проверкой баланса, суммы и пригодности курса.
- Просмотр остатков и расчёт стоимости портфеля в выбранной валюте через сохранённые курсы к USD.
- Получение котировок из **CoinGecko** (криптовалюты) и **ExchangeRate-API** (фиатные валюты).
- Просмотр прямых и расчётных кросс-курсов с попыткой автоматического обновления устаревших значений; фильтрация и рейтинг самых дорогих криптовалют.
- Контроль срока актуальности (**TTL**) каждой валютной пары, отдельное хранение последних курсов и истории наблюдений.
- Ручное и периодическое обновление данных, обработка частичных отказов провайдеров, журналирование и автоматические тесты.

## Конфигурация

Настройки приложения находятся в `src/valutatrade_hub/infra/settings.py`, конфигурация парсера — в `src/valutatrade_hub/parser_service/config.py`.

| Переменная окружения | Назначение | Значение по умолчанию |
|---|---|---|
| `EXCHANGE_RATE_API_KEY` | Ключ ExchangeRate-API | Не задан |
| `EXCHANGERATE_API_KEY` | Альтернативное имя ключа, поддерживаемое конфигурацией парсера | Не задан |
| `COINGECKO_API_KEY` | Необязательный ключ CoinGecko, если необходим выбранному режиму API | Не задан |
| `VALUTATRADE_RATES_TTL` | TTL курса в секундах | `3600` |
| `VALUTATRADE_DATA_DIR` | Каталог рабочих JSON-файлов | `data/` в корне проекта |

Пример настройки ключа для текущей сессии терминала macOS/Linux:

```bash
export EXCHANGE_RATE_API_KEY="ВАШ_КЛЮЧ"
```

Проверить, задан ли ключ, не раскрывая его значение:

```bash
uv run python -c "import os; print(bool(os.getenv('EXCHANGE_RATE_API_KEY')))"
```

Не записывайте настоящие ключи и пароли в Git, README и журналы. Переменная `EXCHANGE_RATE_API_KEY` — основной вариант для интеграции с настройками приложения. Альтернативное имя `EXCHANGERATE_API_KEY` предусмотрено в `ParserConfig`; при настройке приложения предпочтительно использовать основное имя.

По умолчанию парсер отслеживает валютные пары относительно USD:

- **Криптовалюты:** `BTC_USD`, `ETH_USD`, `SOL_USD` (CoinGecko).
- **Фиатные валюты:** `EUR_USD`, `GBP_USD`, `RUB_USD` (ExchangeRate-API).

USD — базовая валюта котировок API и расчётов торгового сервиса. Реестр Core Service теперь поддерживает все шесть отслеживаемых валют, включая GBP и SOL; сделки требуют наличия актуальных курсов и достаточного USD-баланса.

В конфигурации парсера тайм-аут HTTP-запроса по умолчанию составляет 10 секунд.

## Запуск

### Торговый интерфейс

```bash
uv run valutatrade-hub
```

После запуска появится приглашение `valutatrade>`. Команды из таблицы ниже вводятся **внутри приложения**, без префикса `uv run`.

| Команда | Назначение |
|---|---|
| `help` | Справка |
| `register --username student` | Регистрация; пароль запрашивается интерактивно |
| `login --username student` | Вход; пароль запрашивается интерактивно |
| `logout` | Завершение сессии |
| `deposit 10000` | Пополнение виртуального USD-баланса |
| `show-portfolio --base USD` | Баланс, оценка каждого кошелька и общая стоимость в USD |
| `buy --currency BTC --amount 0.01` | Покупка BTC за USD |
| `sell --currency BTC --amount 0.005` | Продажа BTC за USD |
| `get-rate --from BTC --to USD` | Курс BTC/USD; при отсутствии или истечении TTL выполняется попытка обновления |
| `get-rate --from BTC --to EUR` | Расчётный курс BTC/EUR через сохранённые котировки к USD |
| `show-rates --currency BTC --top 5 --base USD` | Фильтрация списка сохранённых курсов |
| `show-rates --top 5 --base EUR` | Топ-5 криптовалют по цене с пересчётом в EUR |
| `update-rates` | Попытка обновления данных от обоих провайдеров |
| `update-rates --source coingecko` | Обновление только CoinGecko |
| `update-rates --source exchangerate` | Обновление только ExchangeRate-API |
| `exit` | Завершение программы (`quit` — синоним) |

Интерфейс также принимает прежние позиционные варианты команд, например `register student`, `login student`, `buy BTC 0.01`, `sell BTC 0.005` и `get-rate BTC`.

Для `register` и `login` также реализован необязательный параметр `--password`, но **рекомендуется интерактивный ввод**: передача пароля в командной строке может раскрыть его через историю команд или запись терминала.

Для операций, изменяющих портфель, требуется авторизация. Курсы отображаются с указанием источника, времени обновления и/или признака актуальности, когда эта информация доступна.

### Периодический планировщик

Запускается отдельным процессом, например во втором терминале:

```bash
uv run valutatrade-scheduler
```

По умолчанию проверка выполняется с интервалом **60 секунд**. Планировщик вызывает `RatesUpdater.update_rates(force=False)`: при достаточной актуальности кэша повторный запрос не нужен, при истечении TTL предпринимается обновление. Ошибки предусмотренных типов записываются в журнал; цикл продолжает работать. Остановка — `Ctrl+C`.

Планировщик не запускается автоматически вместе с торговым CLI.

## Как устроено хранение курсов

### `data/rates.json` — актуальный кэш

Файл хранит последние известные значения по валютным парам. Для каждой современной записи предусмотрены `rate`, `updated_at` и `source`, а верхнеуровневое поле `last_refresh` отражает время обновления кэша.

Пример **структуры** (числа и время условные, не текущие рыночные котировки):

```json
{
  "pairs": {
    "BTC_USD": {
      "rate": 50000.0,
      "updated_at": "2026-11-09T10:00:00Z",
      "source": "CoinGecko"
    }
  },
  "last_refresh": "2026-11-09T10:00:00Z"
}
```

У каждой пары собственная временная отметка. При частичном обновлении получение свежего курса одной валюты **не делает автоматически актуальными остальные пары**. Формат прежнего кэша с числовыми значениями поддерживается на переходный период.

### `data/exchange_rates.json` — история наблюдений

Файл представляет собой JSON-массив отдельных наблюдений курса. Каждое наблюдение содержит уникальный идентификатор, валюты пары, значение курса, время получения и источник (при наличии также метаданные).

Схематичный пример одной записи:

```json
{
  "id": "BTC_USD_2026-11-09T10:00:00Z",
  "from_currency": "BTC",
  "to_currency": "USD",
  "rate": 50000.0,
  "timestamp": "2026-11-09T10:00:00Z",
  "source": "CoinGecko"
}
```

Записи истории добавляются с защитой от повторения идентификаторов. Сохранение выполняется через временный файл с последующей заменой целевого. При ошибках обновления предусмотрена защита ранее сохранённых данных; отдельные случаи восстановления дополнительно проверяются тестами.

Для перевода старой истории к новому формату предусмотрен скрипт `scripts/migrate_rates_history.py`. Перед повторным применением к существующим данным рекомендуется проверить его параметры и сохранить резервную копию файлов.

### Срок актуальности (TTL)

При торговых операциях проверяется временная отметка **необходимой валютной пары**, а не только общий `last_refresh`. Курс не пригоден для торговли, если отсутствует, некорректен, не имеет корректной временной отметки, датирован будущим или достиг заданного TTL. В таких ситуациях необходимо обновить данные через `update-rates`.

Кросс-курсы в CLI вычисляются через USD по формуле `курс A/USD ÷ курс B/USD`; это расчётное значение на основе сохранённых котировок, а не обязательно отдельная котировка провайдера.

Сервис обновления последовательно запрашивает доступные источники. Если один поставщик не ответил, успешные данные другого могут быть сохранены; при отказе всех выбранных источников обновление завершается ошибкой. История и кэш используются отдельно, а ошибки их записи обрабатываются явно.

## Тестирование и качество кода

Полный набор тестов:

```bash
uv run python -m unittest discover -s tests -q
```

Отдельные тесты CLI и обновления курсов:

```bash
uv run python -m unittest discover -s tests -p "test_cli.py" -v
uv run python -m unittest discover -s tests -p "test_updater.py" -v
```

Анализ и проверка форматирования:

```bash
uv run ruff check .
uv run ruff format --check .
```

**Проверка оригинальной версии на MacBook (10.11.2026):** `Ran 330 tests ... OK`; Ruff успешно пройден. После уточнения требований МИФИ добавлено 9 регрессионных тестов: **339 тестов** успешно пройдены в изолированной среде Python 3.13 с временной подменой только вывода PrettyTable. Изменённую версию необходимо повторно проверить на MacBook с реальными зависимостями и Ruff. Тесты не доказывают доступность внешних API в момент запуска.

При тестировании специально воспроизводятся ошибки HTTP-провайдеров, записи файлов и торговых операций. Поэтому строки `WARNING`, `ERROR` и traceback в журнале могут быть ожидаемым выводом теста; итоговый результат определяется статусом `OK` или `FAILED`.

## Логирование и безопасность

- Журналы настраиваются через `logging_config.py` и сохраняются в `logs/valutatrade.log` с ротацией.
- Декораторы фиксируют состояние и продолжительность торговых операций, а также типы ошибок.
- Для типичных записей секретов предусмотрено маскирование, но оно не заменяет запрет на запись ключей и паролей в логи.
- `.gitignore` исключает рабочие пользовательские данные, портфели, кэш курсов, историю, логи, окружение `.env` и локальные резервные копии `backups/`.
- Проект предназначен для обучения; промышленная защита и полноценная транзакционная инфраструктура не реализуются.

## Контрольный список перед сдачей

1. `uv sync` успешно завершается.
2. `uv run ruff check .` и `uv run ruff format --check .` проходят без замечаний.
3. `uv run python -m unittest discover -s tests -q` завершается `OK`.
4. `uv run valutatrade-hub` запускается; команды `help`, `show-rates`, `exit` работают.
5. При наличии доступа к API отдельно проверена команда `update-rates` и сохранение файлов.
6. Проверены `git status` и `git diff --cached`; рабочие JSON, логи и секреты не входят в коммит.
7. Изменения закоммичены и отправлены в нужный репозиторий GitHub.
