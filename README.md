
# ValutaTrade Hub

**ValutaTrade Hub** — учебная платформа виртуальной торговли валютами, разработанная на Python в рамках магистерской программы НИЯУ МИФИ.

Приложение позволяет регистрировать пользователей, управлять виртуальными валютными портфелями, покупать и продавать валюты за USD, получать обменные курсы из внешних API и контролировать их актуальность.

Проект реализован в виде консольного приложения с отдельным сервисом периодического обновления валютных курсов.

> Все операции выполняются с виртуальными средствами. Приложение не осуществляет реальные финансовые транзакции.

## 1. Основные возможности

### Пользователи

- Регистрация новых пользователей.
- Авторизация по имени пользователя и паролю.
- Завершение пользовательской сессии.
- Раздельное хранение портфелей пользователей.
- Проверка корректности регистрационных данных.

### Валютные операции

- Пополнение виртуального USD-баланса.
- Покупка валют за USD.
- Продажа валют за USD.
- Проверка достаточности средств.
- Предотвращение операций с некорректными суммами.
- Сохранение состояния портфеля после успешной операции.
- Защита от частичного изменения портфеля при отклонённых сделках.

### Валютный портфель

- Просмотр всех валютных кошельков.
- Просмотр текущих остатков.
- Расчёт общей стоимости портфеля в USD.
- Сохранение портфеля между запусками.
- Изоляция данных разных пользователей.

### Валютные курсы

- Получение криптовалютных курсов через CoinGecko.
- Получение фиатных курсов через ExchangeRate API.
- Сохранение полученных курсов.
- Проверка актуальности данных по TTL.
- Принудительное обновление курсов.
- Автоматическая периодическая проверка и обновление.
- Обработка ошибок внешних API.

### Дополнительные возможности

- Интерактивный командный интерфейс.
- Отдельный запуск планировщика.
- Централизованное логирование.
- Ротация лог-файлов.
- Частичная маскировка конфиденциальных данных в журналах.
- Автоматическое тестирование.
- Статический анализ и форматирование кода.

## 3. Архитектура приложения

Приложение разделено на несколько функциональных слоёв.

### 3.1. Бизнес-логика — core

Включает модели предметной области и операции над ними.

Основные файлы:

- `models.py` — пользователи, валютные кошельки, портфели.
- `currencies.py` — поддерживаемые валюты.
- `exceptions.py` — специализированные исключения.
- `usecases.py` — регистрация, авторизация и торговые операции.
- `utils.py` — вспомогательные функции.

Бизнес-логика отделена от пользовательского интерфейса и механизмов хранения данных.

### 3.2. Инфраструктура — infra

Включает компоненты конфигурации и постоянного хранения.

- `settings.py` — загрузка настроек приложения.
- `database.py` — чтение и запись JSON-файлов.

### 3.3. Сервис валютных курсов — parser_service

Отвечает за взаимодействие с внешними источниками и обновление курсов.

- `api_clients.py` — API-клиенты CoinGecko и ExchangeRate API.
- `config.py` — конфигурация сервиса.
- `storage.py` — вспомогательные механизмы хранения.
- `updater.py` — проверка актуальности и обновление курсов.
- `scheduler.py` — периодическая проверка курсов.

### 3.4. Пользовательский интерфейс — cli

- `interface.py` — интерактивный интерфейс командной строки.

CLI использует сервисы бизнес-логики, не реализуя торговые расчёты непосредственно в интерфейсе.

### 3.5. Общие компоненты

- `logging_config.py` — настройка централизованного логирования.
- `decorators.py` — декоратор логирования операций.
- `__init__.py` — точка входа консольного приложения.

## 6. Настройка приложения

Настройки реализованы в классе `SettingsLoader`.

Файл:

```text
src/valutatrade_hub/infra/settings.py
```

Основные параметры задаются через переменные окружения.

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `EXCHANGE_RATE_API_KEY` | Ключ доступа к ExchangeRate API | Не задан |
| `VALUTATRADE_RATES_TTL` | Срок актуальности курсов в секундах | 3600 |
| `VALUTATRADE_DATA_DIR` | Каталог хранения JSON-файлов | `data/` |

### 6.1. Настройка ExchangeRate API

Для получения фиатных валютных курсов используется ExchangeRate API.

Базовый адрес API:

```text
https://v6.exchangerate-api.com/v6
```

Необходимо получить ключ доступа у поставщика API.

На macOS и Linux ключ можно задать в терминале:

```bash
export EXCHANGE_RATE_API_KEY="ВАШ_API_КЛЮЧ"
```

Значение переменной должно содержать действующий ключ.

Нельзя добавлять реальные API-ключи в исходный код, README или Git.

Для проверки наличия ключа без вывода его значения:

```bash
uv run python -c "import os; print('API key configured:', bool(os.getenv('EXCHANGE_RATE_API_KEY')))"
```

### 6.2. Настройка CoinGecko

Для криптовалютных курсов используется CoinGecko.

Базовый адрес API:

```text
https://api.coingecko.com/api/v3
```

Доступность запросов и ограничения использования зависят от условий внешнего API.

### 6.3. Настройка TTL

TTL (Time To Live) — максимально допустимый срок актуальности сохранённых валютных курсов.

По умолчанию:

```text
3600 секунд = 1 час
```

Для изменения значения:

```bash
export VALUTATRADE_RATES_TTL=3600
```

Значение должно быть положительным целым числом.

### 6.4. Настройка каталога данных

По умолчанию данные хранятся в директории `data/` в корне проекта.

Для изменения:

```bash
export VALUTATRADE_DATA_DIR="./data"
```

Для использования отдельной директории можно передать другой путь.

### 6.5. Важное замечание о переменных окружения

Команда `export` устанавливает переменную для текущей сессии терминала и процессов, запущенных из неё.

При открытии новой сессии переменную может потребоваться задать повторно.

## 7. Режимы запуска

В проекте предусмотрены две независимые точки входа.

### 7.1. Торговый CLI

```bash
uv run valutatrade-hub
```

Приложение запускает интерактивный интерфейс:

```text
ValutaTrade Hub
Учебная платформа торговли валютами.
Введите help для просмотра команд.

valutatrade>
```

После появления приглашения `valutatrade>` можно вводить команды приложения.

Для просмотра доступных команд:

```text
help
```

Для завершения:

```text
exit
```

### 7.2. Планировщик обновления валютных курсов

```bash
uv run valutatrade-scheduler
```

Планировщик работает отдельно от торгового CLI.

По умолчанию проверка выполняется каждые 60 секунд.

При проверке используется:

```python
RatesUpdater.update_rates(force=False)
```

Если сохранённые курсы актуальны, повторная загрузка не требуется.

Если TTL истёк, сервис пытается получить новые данные.

При временных ошибках API или хранилища планировщик регистрирует ошибку и продолжает работу.

Для остановки процесса:

```text
Ctrl + C
```

Важно: планировщик не запускается автоматически вместе с торговым CLI. При необходимости оба режима запускаются отдельно.

## 11. Контроль актуальности курсов

Перед операциями `buy` и `sell` выполняется проверка времени последнего обновления валютных курсов.

Торговая операция отклоняется, если:

- Время обновления отсутствует.
- Временная метка имеет некорректный формат.
- Временная метка не содержит часового пояса.
- Время обновления находится в будущем.
- Возраст курса достиг установленного TTL или превысил его.
- Не найден необходимый курс.

В случае устаревших курсов необходимо выполнить:

```text
update-rates
```

Пополнение USD не зависит от актуальности курсов.

Просмотр портфеля остаётся доступным, а его оценка может использовать последние сохранённые курсы. Если они устарели, полученная оценка не является текущей рыночной стоимостью.

## 13. Обработка ошибок

В проекте реализованы специализированные исключения.

Примеры:

- `ValutaTradeError` — базовый класс ошибок приложения.
- `InsufficientFundsError` — недостаточно средств.
- `CurrencyNotFoundError` — валюта или курс не найдены.
- `ApiRequestError` — ошибка работы с внешним API или соответствующей операцией обновления.

Обрабатываются также ошибки пользовательского ввода, файловой системы и некорректных числовых значений.

При неуспешной торговой операции изменения портфеля не должны сохраняться.

В тестах отдельно проверяются случаи недостаточного баланса, ошибок сохранения и переполнения числовых значений.

## 14. Логирование

В проекте используется централизованное логирование.

Основной файл журнала:

```text
logs/valutatrade.log
```

Настройка реализована в:

```text
src/valutatrade_hub/logging_config.py
```

Основные параметры:

| Параметр | Значение |
|---|---|
| Уровень логирования | INFO |
| Максимальный размер файла | 5 000 000 байт |
| Количество резервных файлов | 3 |
| Формат хранения | UTF-8 |
| Обработчик файлов | RotatingFileHandler |

Журналы записываются в файл и выводятся в консоль.

Для операций предусмотрен декоратор `log_operation`, который может регистрировать:

- Начало выполнения.
- Успешное завершение.
- Продолжительность операции.
- Тип исключения при ошибке.

Декоратор не записывает аргументы функций, возвращаемые значения или тексты исключений.

### Защита конфиденциальных данных

Фильтр логирования маскирует некоторые распространённые шаблоны:

- `password`
- `passwd`
- `api_key`
- `token`
- `secret`
- `Bearer`

Фильтрация основана на шаблонах и не гарантирует обнаружение любых конфиденциальных значений.

Пароли, ключи доступа и другие секреты не должны передаваться в журнал намеренно.

Папка `logs/` исключена из Git.

## 17. Безопасность

При разработке учитываются следующие принципы:

1. Реальные финансовые операции не выполняются.
2. Пользовательские портфели разделены.
3. Торговые операции проверяются перед сохранением.
4. Устаревшие курсы не используются для покупки и продажи.
5. API-ключи передаются через переменные окружения.
6. Рабочие файлы с пользовательскими данными исключены из Git.
7. Рабочие журналы исключены из Git.
8. Логирование операций не должно раскрывать пароли и ключи.
9. Ошибки внешних API обрабатываются без аварийного завершения планировщика при предусмотренных сценариях.

### Ограничения

ValutaTrade Hub является учебным проектом и не предназначен для промышленной эксплуатации.

В частности, проект не реализует полноценную банковскую инфраструктуру, реальные платёжные операции, промышленную базу данных, распределённую обработку транзакций или систему управления реальными финансовыми рисками.
